# 绘图范围与空闲唤醒：preview.14

日期：2026-10-26。测试为 Windows x64 桌面上的物理像素坐标，使用两张合成图片、同一份隔离配置，无托盘登记。

用户报告 DWM 持续高占用后，现场读取到一个 3840×1080 的透明绘图窗口和一个约 325×183 的照片交互窗口。短时系统性能计数采样未复现持续满载；DWM 样本为 16%、5%、0% 单核等效，分别约为全机 1%、0.31%、0%。这不能排除早先或其他负载组合下的异常。

## 对照方法

先在原实现中只加入观测计数，再分别验证定时器改动和画布改动。暂停、两次换图之间、隐藏三个阶段各测约 2.2 秒。没有高频截图、录屏或屏幕逐像素采样。

| 指标 | 原行为 | 只改定时器 | 最终修复 |
| --- | --- | --- | --- |
| 可见静止唤醒 | 约 64 次/秒 | 约 4 次/秒 | 约 4 次/秒 |
| 隐藏唤醒 | 约 64 次/秒 | 约 1 次/秒 | 约 1 次/秒 |
| 样例绘图窗 | 3840×1080 | 3840×1080 | 281×402 |
| 空闲重复合成提交 | 0 | 0 | 0 |

原实现的空闲重绘和提交计数为零，因此不能把问题直接归为“应用每次定时都在重绘”。实际确认的问题是全桌面大小的透明窗口和持续高频唤醒。最终样例的窗口面积减少约 97%，这表示窗口范围变化，不是同幅度的 CPU 或 GPU 内存下降结论。

## 实现

绘图窗口保留原有透明与不激活行为，新增父视觉节点抵消画布原点。照片、固定角和交互继续使用原有逻辑桌面坐标；画布只容纳相框与过渡范围。换图时复用已经扩展的包络，避免动画中逐帧调整原生窗口或收尾缩窗。拖动、缩放及显示器变化会更新定位。

静止可见时每 250 毫秒检查一次，隐藏或临时暂停时每秒一次；动画、缩略图和大图加载期间使用较快计时。解码完成仍由消息通知，不等待下一次低频计时。合成动画的曲线和时间轴继续由 DirectComposition 推进。

## 验证范围

- 6 组默认回归，包含空闲零重复提交、低频唤醒和画布范围检查。
- 四个固定角、四种效果、208 次连续横竖切换：照片顺序正确、固定角偏移不超过 1 像素、绘图窗覆盖照片且没有扩大回双屏范围。
- 9 项边沿缩放，13 项负坐标显示器和前台交互检查。
- 30 项小区域边缘颜色与圆角命中检查；三个窗口尺寸倍率不等于三个真实系统 DPI。
- 最终安装包的独立目录安装、内容哈希、许可证、启动与退出。
- 无新增测试托盘记录。

连续换图检查的是实际窗口几何与播放状态，不能替代录屏黑闪检查或硬件呈现掉帧统计。真实系统 DPI、跨屏目视与完整长期性能验收仍未全部完成。旧版原始边沿脚本存在坐标错误，在 preview.13 上同样失败；修正后保留原尺寸断言，对实际交互窗口转换坐标并恢复测试光标位置。
